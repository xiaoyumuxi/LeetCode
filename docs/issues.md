# 问题与验收缺口

截至 2026-11-24，本清单记录真实遇到的限制。源码独立维护于 [xiaoyumuxi/LeetCode](https://github.com/xiaoyumuxi/LeetCode)，新增问题与贡献在该仓库的 Issues / PR 处理；下列序号是本文编号，不冒充 GitHub Issue 编号。

| 编号 | 问题、影响与证据 | 当前处理与未完成项 |
| --- | --- | --- |
| 1 | 原生 Plugin View 的事件处理窗口约 2 秒，网络请求与判题等待可能超过窗口。 | 使用公开网页桥接与官方 Go SDK 后端；不改桌面端为力扣特判。需要原生界面时应先设计通用异步 View 能力。 |
| 2 | 依赖的公共 API、Go SDK 与契约未确认随稳定版发布。 | 固定 `sdk.lock.json` 的提交；宿主 [#2372](https://github.com/1lck/Lithe-IDEA/pull/2372)、Core [#194](https://github.com/Lithe-IDEA/Lithe-core-rust/pull/194) 已合入。当前仅供开发安装，不上市场、不宣称兼容稳定版。 |
| 3 | 旧版桌面安装操作的自动化曾受无障碍动作限制。 | 用户已自行从磁盘安装 0.1.0，并反馈题库和解题文件创建可用；这不代表最后 0.0.1 改动已验收。按最新要求不再自动操作或重启用户应用。 |
| 4 | 没有由用户手动输入的真实账号凭据。 | 不读取浏览器数据；登录、在线样例、真实提交、判题及其取消/恢复保持 pending。禁止把离线协议测试当作真实判题。 |
| 5 | 站点接口没有兼容性承诺，可能返回 403、429 或变更 GraphQL 字段。 | 只请求固定两站、不跟随重定向、不自动重试上传。403/429 和结构不兼容返回受控错误，用户在浏览器完成站点验证后手动重试。 |
| 6 | 上传请求超时或连接中断时，远端可能已经接收代码却未返回任务 ID。 | 不自动重发；在原网站检查提交记录。拿到任务 ID 后立即保存，之后查询只发送 ID。未拿到 ID 的远端任务不能自动恢复。 |
| 7 | 首版题面为清洗后的只读文本。 | 图片、公式和会员题在原网站查看；后续如需完整富文本应另定资源与内容安全方案。 |
| 8 | 当前契约不能翻译工具窗口/命令标题。 | 两种语言共用产品名 `LeetCode`；插件页面、提示、错误和确认文字由插件自己的中英词条提供。 |
| 9 | 源码需由个人仓库独立维护。 | 已建立个人仓库，默认分支为 `main`；源码、测试、翻译、功能矩阵和资源说明都在该仓库。本次 `0.0.1` 为 GitHub 预发布，尚未上架市场。 |
| 10 | 力扣的 VS Code 授权入口回调 `vscode://`；此前调查的 Lithe 专用授权路由返回 404。 | 「在浏览器登录」打开官方登录页，但不冒充插件已登录。关联仍需手动输入凭据；不注册或劫持 VS Code scheme，不读取浏览器 Cookie 数据库。自动回传仍未实现。 |
| 11 | 用户反馈题解、讨论按钮显示英文键名且请求失败。源码显示旧后端词条会覆盖新页面词条；旧动作或错误分类经过网页桥接后会丢失。 | 已补中文站社区 API、页面静态词条合并与版本检查；宿主 [#2383](https://github.com/1lck/Lithe-IDEA/pull/2383) 修复结构化错误码。必须完整更新插件，宿主错误分类修复也需要更新宿主；最终组合未验证。国际站社区仍未接入。 |
| 12 | 判题报告此前显示在「输出」，不符合用户希望进入「运行」的工作流。 | 已改用 `run/start` 和打包程序的短时报告模式，不新增 Core API。Run 只管理已完成报告；远端任务取消仍在插件。真实账号和最终界面按用户要求交由用户验收。 |
| 13 | 用户反馈 WebView 遮挡编辑器浮层。 | 宿主通用修复为工作台浮层使用 Viva 的覆盖层，插件无需特判。代码层回归在用户免验证前已运行；原生 WebView 叠层最终效果尚未验收。 |

性能与常驻内存没有原生窗口实测数据；不能据此宣称比原生界面更省资源。后端按需启动，列表有条数和可见节点上限，没有空闲联网轮询。Windows 不在本轮验收范围。

图标接线：插件已声明包内 SVG；宿主原来只读取内置图标 ID，现已补齐包图标加载。使用 `sdk.lock.json` 指定的宿主修订，最后接线未执行验证。
